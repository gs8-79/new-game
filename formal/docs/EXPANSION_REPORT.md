# 《燧火纪：部落黎明》大型扩展版课程设计报告

## 1. 项目概述

本项目是一款使用 C++17、STL、CMake 和 Visual Studio 2026 开发的单机文字策略 MUD。大型扩展的最终目标是让玩家代表整个部落，管理具名人物、小队、装备、外交、贸易、战争与内部稳定。

扩展采用两次迭代。当前 V1 只完成一条可以从营地出发、在苍林采集、遭遇外族、和平贸易或进入战斗、拾取装备并回营的纵切路线；六部落、16地点、内部稳定和长期战役仍是 V2 蓝图，不是当前已完成功能。

四张设计图统一区分 V1 与 V2，见 [EXPANSION_DIAGRAMS.md](EXPANSION_DIAGRAMS.md)。

## 2. 需求分析与OOA

### 2.1 目标参与者（V2蓝图）

- 玩家：创建部落、培养人物、编组小队、外交、贸易、战斗和选择结局。
- 其他部落AI：计划根据资源、关系、首领和派系自主行动，V1尚未接入。
- 季节系统：计划结算消耗、常驻任务、外交变化和结局条件，V1扩展试玩尚未接入。

### 2.2 V1实际参与者与用例

V1实际参与者只有玩家。玩家从主菜单进入扩展试玩，选择2至8人小队或固定种子，执行探索、采集、交谈、贸易、劫掠、战斗、拾取、装备和回营结算。

### 2.3 主要对象

- `Character`：具名角色及其属性、经验、疲劳和装备。
- `Squad`：2至8人的作业小队，包含队长、成员、任务和凝聚力。
- `Army`：战争时由统帅、正式战士和民兵组成的临时军队。
- `Item`、`Inventory`：个人装备、战利品、重量和格数限制。
- `ExpansionGame`：苍林任务的阶段、命令和原子状态修改。
- `GameEngine`：保留旧正式模式的季节经营规则。
- `SaveRepository`：严格解析、保存、备份和恢复旧正式模式的 `GameState`；V1的 `ExpansionState` 尚未持久化。

## 3. OOD与模块职责

V1没有把新规则继续塞入原有千行引擎，而是建立独立的扩展领域层：

- `expansion_types` 只处理人物、小队、军队、装备和背包规则。
- `expansion_game` 只处理苍林任务、遭遇和可操控战斗。
- `GameEngine` 继续处理旧正式模式，并先修复已确认的规则漏洞。
- `ConsoleUI` 负责整屏显示，不直接修改状态。
- `SaveRepository` 负责旧正式模式的文件可靠性，不决定玩法；扩展状态的版本2存档留到V2。

所有行为使用“复制候选状态→完整校验→一次提交”。条件不足、非法命令和背包超限都不会扣资源或留下半次修改。

## 4. V1玩法实现

### 4.1 角色和成长

角色拥有力量、敏捷、体魄、感知、生存、交涉、意志、统率八项属性。升级获得1个成长点，可以手动加点，也可以按职业一键推荐。疲劳会降低速度和战斗表现；休整同时受生命上限和疲劳下限保护。

### 4.2 装备和背包

个人装备栏固定为主手、副手、头部、身体、手部、腿足、工具、饰品。装备损坏时只提供一半加成，报废装备不能穿戴。背包同时检查重量和格数；拾取失败时状态不变。

### 4.3 苍林任务和战斗

任务依次经过营地准备、森林探索、外族遭遇、三段战线战斗、回营结算。玩家每回合操控队长，队员根据军令自动跟随。速度影响先手和闪避；疲劳越高，速度越低。战斗胜利后拾取不消耗回合，战斗中禁止换装。

### 4.4 可靠性修复

- 守卫加成保留到真正处理下一次岩牙来袭后再清零。
- 岩牙在来袭战中被击溃后，允许占领空要塞并完成征服道路。
- 非法战术返回错误，不再解引用空策略。
- 自动保存失败时保留当前局，并提供重试、另存、取消。
- 主档损坏或缺失时，只从通过完整校验的 `.bak`、`.tmp` 恢复。

## 5. STL与设计思想

- `std::array` 保存固定八项属性和八个装备栏。
- `std::vector` 保存小队成员、背包物品和命令参数。
- `std::optional` 表示空装备栏和非装备物品。
- `std::unordered_set` 检查角色名和物品编号是否重复。
- `std::clamp`、`std::min`、`std::max` 控制生命、疲劳、忠诚和资源范围。
- 战术模块继续使用策略模式；存档使用仓库职责；扩展内容采用状态机和候选状态原子提交。

## 6. 测试报告

本项目在 CMake 中注册2个 CTest 测试程序，两个程序内部共有83个 `TEST_CASE`：旧三个 Demo 33项，正式版与扩展版50项。扩展测试覆盖属性加点、多级升级、八栏装备、损坏加成、背包容量、休整、小队人数、军队基础类型合法性、和平贸易、中文英文等价、自动跟随、三段战线、队长阵亡、撤退、免费拾取、战中禁换装、失败原子性和固定种子重现。

证据等级：代码与 CMake 接线已确认；本地 Visual Studio 2026 完整 Release 为33/33和50/50，独立 Formal-Debug 为50/50；Windows中文和平路线与固定种子战斗路线完成本机程序烟测，转录见 [V1_SMOKE_TEST.md](V1_SMOKE_TEST.md)。Mac脚本存在但未做Mac实机构建；V1试玩ZIP、交换组试玩和课堂验收也未完成，不能写成已交付或跨平台验证完成。

### 6.1 测试方法与问题处理

- 单元测试直接调用领域规则，检查合法动作和失败原子性。
- 路线测试从营地出发走完和平与战斗闭环。
- 回归测试每次同时运行旧三个 Demo，防止正式扩展破坏原型。
- 审查发现“阵亡角色仍可吸收攻击并继续作战”，已改为只选择存活目标，队长阵亡立即结束任务并补回归测试。
- 审查发现“装备后物品仍留在背包且可重复装备”，已改为背包取出、旧装备回收和重复操作原子拒绝。
