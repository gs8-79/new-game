# 正式版与V2战役存档格式

## 1. 旧正式模式（版本1）

- 格式为 UTF-8 键值文本，每行一个 `key=value`。
- 固定头为 `format=tribe-dawn`、`version=1`。
- 文件为 `saves/formal/slot1.sav`、`slot2.sav`、`slot3.sav`、`autosave.sav`。
- 数组使用英文逗号分隔的整数，字符串字段只接受程序内已知标识符。

### 1.1 字段

存档包含模式、事件种子、季节、小队数、全部资源、战士、士气、营地耐久、岩牙战力、游戏阶段、结局、强制敌袭、停战与要塞状态，以及地点发现/侦察、建筑、技术、三个部落关系与任务阶段、16季事件表和当前事件。

### 1.2 加载规则

1. 将文件解析到全新的 `GameState`。
2. 拒绝重复键、未知键、缺字段、非整数和超范围数字。
3. 检查数组长度、枚举编号、模式与季节范围、战士不超过人口、结局与阶段一致。
4. 检查事件编号合法，固定剧情事件位于规定季节。
5. 全部通过后才替换当前状态；任何错误都保持原游戏不变。

### 1.3 保存规则

1. 保存前调用与加载相同的状态校验。
2. 先在内存中序列化并重新解析，确保可往返。
3. 写入同目录 `.tmp` 文件并刷新关闭。
4. 旧档存在时先改名为 `.bak`，再将 `.tmp` 改为正式文件。
5. 替换失败时恢复 `.bak`；成功后删除备份。

## 2. V2长期战役（版本2）

- 文件为二进制数据，固定标识为 `TRIBEV2`，版本号为2，并带负载长度和校验和。
- 路径为 `saves/formal-v2/campaign-slot1.sav` 至 `campaign-slot6.sav`，自动档为 `campaign-autosave.sav`。
- 保存模式、种子、季节、资源、地图、建筑、技术、六部落、外交关系、派系、人物、装备、背包、永久小队、当前任务、战争、首领历史、结局和编年史。
- 单个存档上限16 MiB；人数、小队、背包和编年史等集合均有限制，防止损坏文件造成异常占用。
- V2发布后的长期小队背包以带 `SPK1` 标识的尾部扩展保存。没有该尾部的已发布V2旧档仍可读取，并为每支小队建立合法的空背包；未知、数量不符或损坏的尾部扩展会被拒绝。

### 2.1 V2加载与恢复

1. 先检查标识、版本、长度和校验和，再解析到临时 `CampaignState`。
2. 完整校验枚举、数值范围、人物与小队引用、任务、战争、外交和结局状态。
3. 主文件无效时依次尝试同档位的 `.bak` 和 `.tmp`；只有完整合法的候选状态才交给游戏。
4. 全部失败时保留当前游戏，并显示具体失败原因。

### 2.2 V2保存规则

1. 保存前校验状态，并在内存中完成一次序列化与反序列化往返。
2. 先写`.tmp`并校验，再以原主文件作为`.bak`恢复点，最后替换主文件。
3. 读取恢复文件不会绕过版本、校验和或状态合法性检查。

## 3. 旧正式版到V2的迁移副本

1. 主菜单输入 `migrate <旧档1|2|3|auto> <V2空档1..6>` 或 `升级存档 <旧档> <V2空档>`；迁移不会自动触发。
2. 迁移器用独立只读解析器读取旧主档；主档损坏或缺失时可只读尝试`.bak`和`.tmp`，但绝不把恢复候选复制、重命名或写回旧主档。
3. 旧状态和转换后的V2状态分别在临时对象中做完整校验；任一步失败都不修改当前游戏和目标对象。
4. 兼容字段包括季节、行动点、人口与资源、士气、营地耐久、岩牙状态、九地点发现、建筑、科技、三部落关系和已完成外交阶段。V2新增的六部落档案、人物名单、永久小队与派系沿用合法默认值；旧版非敌袭阶段的临时防御没有V2长期字段，不继续保留，并写入迁移编年史说明。
5. 迁移仅写入1至6中的空V2手动档；已有`.sav`、`.bak`或`.tmp`的目标档位会被拒绝，不使用自动档，也不覆盖任何已有V2数据。

两种格式都不执行脚本、不保存裸指针。V1与V2档案始终彼此分开，迁移只生成经过校验的V2副本。
