## 2. 优化一：地图路线提示（减少迷路）

### 2.1 做了什么

1. 地图目录新增三个纯图算法（`world_map` 命名空间）：
   - `roadDistance(from, to)`：最短路步数，不可达返回 −1；
   - `roadPath(from, to)`：最短路地点序列（保证相邻两项真的相邻）；
   - `nextStepToward(from, to)`：沿最短路的第一步。
   三者都用广度优先搜索，并列路径取编号更小的地点，因此结果**完全可复现**。
2. 任务层新增 `missionRouteHint(const ExpansionState&)`，输出四类提示：
   - 地点档案（风险等级 + 收益 + 现场危险）；
   - 任务状态（能不能结算、剩余采集时段、载货是否已满、遭遇是否封锁道路）；
   - 资源错配提示（“本次指定资源是木材，此地不产；最近产地 2.苍林 3步（北→西→西），输入 move 2”）；
   - 路线提示 + 探索提示（最近结算点、最近未探索地点，含步数、方位链、可直接输入的命令）。
3. `look` / `查看` 的输出末尾追加上述提示；终端地图页底部也显示“路线提示/探索提示”两行。
4. 地图页给已建前哨的节点加上 `★` 标记，图例写明“★=结算点”。

### 2.2 为什么这样做

- 玩家的真实痛点不是“不知道自己在哪”，而是**不知道下一步该往哪走**：`move` 只接受相邻地点，走错一次就要多花 2 点队长疲劳。提示直接把“几步、什么方向、输入什么命令”写出来。
- 计算放在只读函数里而不是存进状态：既不污染存档，也不会出现“提示与实际地图不同步”的问题。

### 2.3 实测效果（摘自 `artifacts/playthrough-transcript.txt`）

```
  图例：金色=当前位置  白色=已发现  灰色=未发现  ★=结算点
  当前 1.燧火营地  已发现 3/16  前哨 0
  路线提示：当前地点即为结算点，可随时 settle 入库。
  探索提示：最近未探索地点 4.芦苇沼泽 2步（西→北），输入 move 4。
```

### 2.4 验证

- 交付测试「十六地点道路图双向连通…」逐对校验 16×16 全部组合：路径首尾正确、逐段相邻、长度等于 `roadDistance`、`nextStepToward` 必定把剩余距离减少 1。
- 交付测试「路线提示给出最近结算点…」校验提示文本，并**真的执行提示里的 `move` 指令**，证明建议可用。

## 3. 优化二：每个地点的风险、奖励与描述

### 3.1 做了什么

新增 `world_map::LocationProfile`（风险等级 0–3 + 风险名 + 可期收益 + 现场危险说明）与 16 条档案，例如：

| 地点 | 风险 | 档案摘要 |
| --- | --- | --- |
| 燧火营地 | 0 安全 | 营地不存在遭遇与采集时段消耗 |
| 白羽营地 | 0 安全 | 友邦营地无战斗风险，但位置偏远、往返步数长 |
| 苍林 | 1 低 | 唯一五项占其四的采集地；林间野兽与密林迷路 |
| 芦苇沼泽 | 2 中 | 沼泽陷足，行军与采集疲劳高于平路 |
| 岩牙要塞 | 3 高 | 敌对巡逻生命 14；未击退不能在要塞建前哨，遭遇期间不能移动 |
| 古老山隘 | 3 高 | 岩牙接触点；撤退时的固定退回点 |

这些文案在 `look/查看` 与地图页上展示，让十六个地点不再只是“编号 + 名字”。

### 3.2 有意为之的取舍：风险等级不做数值机制

- 需求是“补充不同风险、奖励或描述，提升探索差异”，因此本层**只做信息，不改平衡**。
- 风险差异在游戏里本来就存在（要塞有遭遇、沼泽/山隘/矿场里程更远、矿石沉重更容易占满载货），档案把这些差异**说出来**，而不是新造一套数值。
- 好处：既不影响任何既有测试与平衡，也不需要新增存档字段。
- 如果想让它真正影响机制（例如按风险调整疲劳倍率或遭遇表），扩展步骤见 `02-十六地点地图与试玩路线.md` 第 8 节。

### 3.3 验证

- 交付测试校验：全部 16 个地点的档案字段非空、风险均在 0–3、营地风险为 0、要塞与山隘风险为 3、非法地点返回兜底档案且**不抛异常**（渲染路径必须安全）。

## 4. 优化三：核查“采集后未结算不能进入部落仓库”

### 4.1 结论：规则成立，三层共同保证

| 层 | 行为 | 证据 |
| --- | --- | --- |
| 地图层 | `settle` 只把阶段改为 `Settled` 并保留载货，**从不写部落库存** | `formal/src/expansion_game.cpp` `settle`（原注释：“保留载货和背包给上层 GameEngine 统一入账，避免地图层和部落层重复增加资源”） |
| 引擎层 | 只有地图阶段为 `Settled` 时，才一次性把五项载货与任务背包并入库存，随后清空活动任务 | `formal/src/game_engine_mission.cpp` `executeMission` 的 settled 分支 |
| 放弃路径 | `abort` 丢弃载货、`missionCount` 不变、稳定度 −2、仓库零增加 | `formal/src/game_engine_dispatch.cpp` `dispatchMissionCommand` |

### 4.2 补充的三条验证（本次新增）

1. **引擎层**：采集 2 次后 `state.wood` 与出发前完全相等；`settle` 后恰好增加 `cargoWood` 一次（不多不少）。
2. **放弃路径**：`abort` 后仓库不变、任务计数不变、小队回到营地。
3. **存档往返**：任务中的载货被完整写入存档并读回（`turn`、`cargoWood`、`phase` 全部一致），但**读取后仓库仍然没有变化**；接着结算才入账一次。

### 4.3 核查中发现的问题与修复

| 编号 | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |
| M3-1 | `useHerb()` 没有 `phase` 检查：任务已结算后仍可使用草药并推进任务回合 | 单独使用 `ExpansionGame` 时会出现“已结算还能动”的不一致；完整游戏里因为结算后立刻清空活动任务而不可达 | 已在 `useHerb` 加 `phase` 门禁，统一为“任务已结算。” |
| M3-2 | `attackEncounter`/`defendEncounter`/`retreatEncounter` 同样缺少 `phase` 门禁 | 已结算且停在要塞时仍能开战 | 三个函数统一加 `phase` 门禁 |
| M3-3 | 遭遇未激活时输入 `defend`/`retreat`，地图层返回 `recognized = false` | 界面会提示“无法识别该命令”，掩盖真实原因；玩家以为是打错了 | 改为“识别后拒绝”，提示“当前没有遭遇战。” |
| M3-4 | `retreat` 的落点（古老山隘）若未登记为已发现，候选状态会被 `validateState` 判非法，导致**撤退被整体取消**、小队被困在遭遇里 | 正常行军一定先经过古老山隘，因此实际不可达；但属于“失败路径把玩家卡死”的高危形态 | 撤退时顺手把落点标记为已发现（防御性兜底），并新增测试固定该行为 |
| M3-5 | 采集时段上限 `4` 在 `gather()`、`validateState()` 与提示文本里各写一次字面量 | 三处容易改漏，出现“命令允许但状态非法”的分裂 | 提取为 `kMaximumHarvestActions` 常量，三处共用 |

以上均为**单一职责的小修**：不改变任何成功路径的数值结果，只补齐失败路径的一致性。回归证据：既有回归测试全部通过（团队 `main` 33 项 / 本地快照 34 项）。

## 5. 优化四：补齐失败、行动点与错误地点测试

新增 13 个测试用例（详见 `05-测试说明与验收矩阵.md`），覆盖：

- 采集：错误地点、未知资源、混采、满载、时段耗尽、中英文别名等价、食物任务顺带采兽皮；
- 移动：不相邻、未知地点、原地停留、参数缺失、已发现地点不重复提示、结算后禁止移动；
- 前哨建设：材料不足、营地、重复建造、要塞未击退、成功建造后可就地结算；
- 结算：非结算点拒绝、营地结算、前哨结算、结算后全部命令关闭、经验与凝聚力奖励、仅结算入账、放弃任务不入账、存档往返不入账；
- 行动点：行动点耗尽、劳力不足、仓库建材不足、疲劳过高、地图内动作不再消耗季节行动点；
- 遭遇：无遭遇时的防御/撤退拒绝、遭遇期间移动/采集/建造/结算封锁、撤退落点、击退奖励、击退后可建前哨；
- 状态校验：越界地点、未发现地点、越权结算、遭遇字段组合、数值与枚举边界、非法状态不能被接管。
