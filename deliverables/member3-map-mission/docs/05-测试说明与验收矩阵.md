## 5. 断言风格：如何证明“失败路径没有改状态”

交付测试对**每一条**被拒绝的地图命令都做完整快照比较（`snapshotOf` + `snapshotDifferences`），比较 19 个字段：位置、回合、阶段、五项载货、采集时段、结算标记、遭遇血量与击退标记、凝聚力、成员数、队长生命与疲劳、背包件数、前哨数组、已发现数组。任何一项变化都会带着字段名抛出失败信息，例如：

```
失败命令改动了地图状态：gather stone，差异字段：cargoStone turn
```

这比只断言 `!result.success` 强得多：它同时证明了“拒绝”与“原子性”两件事。引擎层的用例则复用项目自带的二进制存档快照手法（`current_game_tests.cpp` 的写法），确保没有隐藏的派生字段被改动。
